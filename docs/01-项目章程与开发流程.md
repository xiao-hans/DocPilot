# 项目章程与开发流程

| 项目 | DocPilot 多租户文档智能处理平台 |

## 1. 项目目的

将当前单机演示型 DocPilot 演进为多个客户可共同使用的通用文档平台。客户能够建立自己的空间、成员、文档类型和提取模板，并逐步获得结构化提取、文档归档与搜索、人工复核、工作流和系统集成能力。

## 2. 项目目标

1. 建立租户、用户、成员、权限和账务用量的基本边界。
2. 提供可靠的文档接收、解析、提取、复核、归档和导出闭环。
3. 让不同客户可配置文档类型、字段和处理规则。
4. 提供可扩展的搜索、自动化和外部集成能力。
5. 建立数据隔离、安全、备份、监控和可运维基础。

## 3. 范围

### 3.1 目标范围

- 多租户 SaaS 产品方向；首期默认以浏览器人工上传作为入口，API/网盘/邮箱导入作为后续能力。
- 文档抽取、人工确认、文档库/搜索和工作流能力，按阶段交付。
- 管理员、租户管理员、成员、复核人员等基本角色。
- 面向未来的 API、异步任务、存储与处理器接口边界。

### 3.2 暂不承诺

- 特定国家或行业合规认证、特定云服务商部署、数据驻留承诺。
- 企业级单点登录、复杂计费、客户自助开通、白标及独立私有部署。
- 无人值守的法律/财务决策；模型输出需可复核，不能视为权威结论。
- 具体容量、可用性、响应时限和保留周期；需经业务确认后基线化。

## 4. 现状基线

当前仓库已有 FastAPI + Vue 3/Vite 应用，支持 PDF/PNG/JPG/JPEG 上传、PDF 文本解析、扫描件/图片 OCR、mock/兼容 OpenAI API 的字段提取、进程内任务管理及 XLSX 导出。当前任务状态存于内存，前端默认固定发票字段，未发现用户/租户、持久化数据库、对象存储、任务队列、审阅工作台或文档搜索模块。当前首页仍有 `app/static/index.html`，需在实施启动前确认其与 Vue 构建入口的部署关系。

## 5. 项目角色（暂定）

| 角色 | 责任 |
|---|---|
| 产品负责人 | 确认目标客户、产品范围、优先级、验收及合规边界 |
| 技术负责人 | 架构、技术选型、安全设计、技术风险和发布决策 |
| 开发人员 | 需求澄清、实现、代码审查、单元/集成验证和文档更新 |
| 测试负责人 | 风险分析、测试设计、执行、缺陷跟踪与发布质量结论 |
| 平台运营/管理员 | 租户开通、套餐策略、平台健康和支持流程 |
| 客户租户管理员 | 管理客户成员、模板、权限及客户侧数据策略 |

小团队可由同一人承担多个角色，但需求批准、实现和发布的责任应在记录中明确。

## 6. 迭代生命周期与阶段门

采用短迭代的需求澄清、设计、实现、验证、发布循环；每项需求必须有负责人、优先级、验收条件和可追踪编号。

| 阶段门 | 通过条件 |
|---|---|
| G0 需求基线 | 用户、首期范围、非目标、关键质量指标和验收条件获确认 |
| G1 架构评审 | 租户隔离、身份与权限、数据存储、任务模型、安全威胁和技术取舍有记录 |
| G2 迭代就绪 | 需求已拆分、依赖明确、测试条件可执行、数据迁移/兼容策略已定义 |
| G3 发布候选 | 自动化测试和安全检查达到门槛；阻断级缺陷清零；回滚与备份恢复方案就绪 |
| G4 发布复盘 | 监控、用户反馈、事件和质量指标已复盘，后续行动已登记 |

## 7. 变更、配置和质量管理

- 文档与代码以 Git 版本控制；需求编号跨 PR、实现和测试保持稳定。
- PR 应说明关联需求、设计变化、数据迁移、安全影响、测试结果和回滚方法。
- 需求范围变更由产品负责人确认影响；涉及租户隔离、个人/客户数据或公开 API 的变更必须经技术负责人和安全责任人评审。
- 发布制品需可追溯到代码版本、数据库迁移和配置版本；密钥不得写入仓库。
- 文档更新与对应功能变更同一迭代完成；过期决策标记为 superseded 并链接替代决策。
- **改了产品函数的行为，就在提交前跑一遍覆盖它的用例。** 动作是
  `.venv/Scripts/python.exe scripts/assertion_sync_check.py --rev WORKTREE --run`：
  它从改动里抽出被改的函数，静态找出调用它们的用例，再真跑一遍。理由是一条真实旧账——
  M1 改了任务列表的排序键却没改要求"按创建顺序倒序"的旧断言，那条断言在新键下只剩约 1/6
  的偶然通过率，几周后必然红，而看到红的人第一反应是"产品坏了"（`docs/06` TC-FUNC-070）。
  这条门禁的边界要一起记住：**它拦得住"忘了看测试"，拦不住"看了但没改对"**——静态那一层
  只能看见测试文件被动过，看不见断言内容是否仍然成立。所以它是提交前的提示与复核入口，
  不是"断言必然同步"的证明。

## 8. 工程标准的裁剪说明

参考 ISO/IEC/IEEE 12207:2026 的生命周期过程思路，不采用重型阶段瀑布；参考 ISO/IEC/IEEE 29148:2018 编写可验证需求；参考 42010:2022 描述架构关切与视图；参考 ISO/IEC/IEEE 29119-2:2021、29119-3:2021 管理测试及测试信息项。当前团队规模、监管背景和正式符合性要求尚未确认，因此不声明标准符合性。
