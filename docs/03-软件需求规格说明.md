## 1. 范围与系统边界

系统为多个客户提供共享服务。平台负责身份/租户上下文、授权、文档元数据与文件引用、异步处理、模板、审阅、搜索、导出、集成事件和运营管理。OCR/LLM 可由内置组件或外部兼容服务提供。首期入口假定为 Web 上传；API 导入待规划。

## 2. 优先级定义

- **P0**：多租户安全和首期闭环必须具备。
- **P1**：完整产品使用体验，应在初始商业化版本提供。
- **P2**：后续增强。

## 3. 功能需求

### 身份、租户与授权

| ID | 优先级 | 需求 | 验收条件 |
|---|---|---|---|
| FR-001 | P0 | 系统应支持用户身份验证及租户成员关系。 | 未认证请求不能访问租户数据；同一用户可按授权加入多个租户。 |
| FR-002 | P0 | 每个业务对象应归属一个租户，服务端应从可信身份上下文解析租户。 | 跨租户读取/更新/删除均被拒绝；不得仅依赖客户端传 tenant_id 授权。 |
| FR-003 | P0 | 系统应提供租户所有者、租户管理员、成员、复核人员和平台管理员等授权能力，并按角色矩阵默认拒绝。 | DOC-DD-003 矩阵中每个"允许/拒绝"格均有自动化用例；矩阵未列出的动作默认拒绝；平台管理员身份不自动获得任何租户访问权。 |
| FR-004 | P1 | 租户管理员应能邀请、停用和移除成员，所有者可变更成员角色。 | 成员变更在下一次请求即影响授权（不依赖会话过期）；历史数据归属不变；所有者不能被自我移除或移除后无剩余所有者。 |
| FR-005 | P1 | 邀请应以一次性、短期有效的随机令牌承载，并绑定目标邮箱与角色。 | 令牌原文只在创建响应中出现一次，库内仅存摘要；过期、撤销、重复使用、邮箱不匹配均被拒绝且无成员关系副作用；同一租户同一邮箱同时至多一条待接受邀请。 |
| FR-006 | P1 | 授权与敏感数据操作应写入只追加的审计事件。 | 成员邀请/接受/撤销/角色变更/移除及结果导出均产生审计记录，含租户、操作者、动作、对象与时间；审计不含文档正文、服务器绝对路径或密钥；不提供修改/删除审计记录的业务接口。 |

### 文档与模板

| ID | 优先级 | 需求 | 验收条件 |
|---|---|---|---|
| FR-010 | P0 | 成员应能上传多个受支持文件并查看校验错误。 | 格式、大小、数量、重复名和损坏文件按策略拒绝或明确报错。 |
| FR-011 | P0 | 系统应安全保存原始文件并关联租户、上传者、时间和校验摘要。 | 重启后文件引用有效；响应不泄露服务器绝对路径。 |
| FR-012 | P1 | 租户管理员应创建、编辑、复制、停用文档类型及字段模板。 | 每次发布生成不可变 `TemplateVersion`；任务绑定其创建时使用的版本；被任务引用的版本不可删除或原地修改；停用只阻止新任务选用，不影响历史任务。 |
| FR-013 | P1 | 文档应支持类型、标签、状态、来源和保留状态等元数据。 | 可按授权范围查询和更新，变更写审计记录。阶段 C 覆盖状态与来源（上传/API/导入）及文档类型（取自模板）；标签、保留状态与批量修改在阶段 D 文档库交付。 |

### 处理、提取和复核

| ID | 优先级 | 需求 | 验收条件 |
|---|---|---|---|
| FR-020 | P0 | 系统应创建持久化异步任务并暴露排队、处理中、成功、部分成功、失败状态。 | 服务重启后状态可读；终态含完成时间和可诊断错误；`queued`/`processing` 任务的归属与租户上下文在恢复后保持一致；状态变更不得把已完成任务重新排队。 |
| FR-021 | P0 | 系统应按文件类型执行文本解析/OCR，并保留页数、识别方式、警告和错误。 | 每个文件单独记录成功或失败，不因单文件失败丢弃整批成功结果；解析得到的原文按文件版本持久化并可供有权限成员预览，预览只返回纯文本。 |
| FR-022 | P0 | 系统应按所选模板提取字段，校验类型并返回来源/置信度（若处理器可提供）。 | 字段、模板版本、处理器版本及原始候选值可追溯；缺失值明确表示；同一任务的字段定义在任务创建时冻结，模板后续发布新版本不改变历史任务；提取结果按 `(任务, 文件版本)` 规范化落库，与任务快照在同一事务提交。 |
| FR-023 | P0 | 有权限的用户应查看原文及字段结果并编辑、确认或退回复处理。 | 修改前后值、用户、时间、理由（如配置必填）可审计；修订历史只追加、不被覆盖；并发保存以数据库层版本号判定，冲突返回 409 而不是静默覆盖；`rejected` 不得直接转 `confirmed`（必须先产生新修订），退回同时清除确认人与确认时间。 |
| FR-024 | P1 | 系统应支持幂等重试并防止并发重复处理造成重复结果。 | 同一租户内相同 `Idempotency-Key` 至多创建一个任务，重复提交返回既有任务标识且响应可判定为复用；不同租户使用相同键互不影响；重试不重复产生导出或其他外部副作用。 |
| FR-025 | P1 | 系统应记录每次任务执行尝试，并对超时或中断的尝试做回收与有界重试。 | 每个任务保留尝试历史（开始/结束、结果、错误、耗时）；`processing` 超过配置时限后被回收为可重试状态；重试次数达到上限即进入 `failed` 并保留可诊断错误；并发 Worker 不得同时执行同一任务。 |

### 文档库、搜索与导出

| ID | 优先级 | 需求 | 验收条件 |
|---|---|---|---|
| FR-030 | P1 | 用户应浏览和筛选本租户的文件、处理任务、模板和审阅状态。 | 列表分页/排序稳定，权限过滤在服务端执行；文档库支持标签、文档类型、来源、保留状态、时间范围与文件名筛选，响应不含存储路径；保留状态属治理面，仅 `admin`/`owner` 可变更。 |
| FR-031 | P1 | 用户应按文档文本、文件名及已提取字段搜索。 | 结果只包含授权租户数据；三类来源（文件名、解析原文、字段值）都能命中并给出上下文片段；人工修订后新值可搜、旧值不再命中且不追加索引行；查询词长度受限、`LIKE` 通配符按字面处理；搜索索引删除与源文档生命周期一致。 |
| FR-032 | P1 | 用户应将确认结果导出为 XLSX/CSV。 | 导出与模板版本匹配；防止公式注入；审计下载行为；存在人工修订时以当前值（而非机器快照）为导出源；两种格式对同一结果给出逐字符相同的可见内容，并遵守 XLSX 的单元格字符上限。 |

### 工作流、集成和运营

| ID | 优先级 | 需求 | 验收条件 |
|---|---|---|---|
| FR-040 | P2 | 租户管理员应配置事件触发的规则、条件及通知/审批动作。 | 规则执行有版本、运行日志、失败重试和禁用能力；默认不执行不安全动作。可订阅事件类型与可执行动作均来自服务端白名单；条件只允许标量比较；每次有效编辑递增版本号且历史日志保留执行时版本；`(事件, 规则, 版本)` 至多一条运行记录，失败重试只推进该记录的尝试次数；动作失败时事件不得被标记为已投递；通知动作只登记投递意图，在没有确认的投递渠道前不得声称已送达。 |
| FR-041 | P2 | 系统应提供版本化 API 与 Webhook。 | 身份认证、签名、幂等、限流、超时、重试和密钥轮换有定义。 |
| FR-042 | P1 | 平台管理员应查看租户状态、资源用量和处理失败摘要。 | 运营视图不绕过审计；客户间数据按平台管理权限隔离。 |

## 4. 质量属性需求

以下为设计目标，具体数值（容量、响应时间、恢复目标）需在 G0/G1 基线确认。

| ID | 属性 | 需求 |
|---|---|---|
| NFR-001 | 安全 | 所有租户拥有者数据访问须经服务端授权；默认拒绝；跨租户隔离需纳入自动化回归测试。 |
| NFR-002 | 隐私 | 文件、OCR 文本、提取结果和模型请求按数据敏感信息处理；默认不得用于训练外部模型；外部处理商及传输范围需明确告知并获授权。 |
| NFR-003 | 可用性 | 持久化数据应有备份、恢复演练和任务恢复策略；RPO/RTO 待产品确认。 |
| NFR-004 | 可扩展性 | 文档解析器、提取器、搜索后端和集成适配器应通过接口替换/扩展。 |
| NFR-005 | 可维护性 | 关键业务操作结构化记录关联 request_id、tenant_id、job_id；日志不得包含密钥或不必要的文档内容。 |
| NFR-006 | 性能 | 上传、查询和导出需支持分页/流式处理；解析和模型调用在后台执行；吞吐目标待负载模型确认。 |
| NFR-007 | 可访问性 | Web 主要流程支持键盘操作、语义结构和状态辅助播报。 |
| NFR-008 | 兼容性 | API 有版本策略；模板和数据模型变更须考虑向后兼容和迁移。 |
| NFR-009 | 可观测性 | 监测队列时延、任务耗时、成功率、OCR/提取失败、存储容量和外部服务错误。 |

## 5. 安全与数据约束

- 文件上传需校验扩展名、MIME/文件签名、大小、数量和内容可读性；隔离解析器资源并限制页数/像素/处理时长。
- 文件名不得直接作为存储路径；下载经鉴权并使用短期受控链接或服务端流式响应。
- 数据模型和查询必须携带租户上下文；后台任务、导出、缓存、搜索索引和 Webhook 也需保持租户隔离。
- 上传文件、抽取文本和用户自定义提示均是不可信输入；不得允许文档内容越权触发工具或流程动作。
- 日志、错误和导出不得泄露其他租户信息、服务器路径、凭据或模型密钥。
- 平台管理员身份不构成租户数据访问权；对客户数据的运营访问必须经显式授权流程并留下审计记录。
- 角色与成员关系判定应在每次请求时从可信存储读取，不得依赖登录时快照或客户端传入的角色。
- 邀请令牌按凭据对待：原文只出现一次，库内仅存摘要，短期有效且可撤销；不得通过邀请接口探测账号是否存在。
- 删除策略需覆盖原文件、派生文本、缩略图、搜索索引、导出和备份边界；法定留存例外需确认。

## 6. 验收与需求管理

每个 P0/P1 需求必须有可复现验收条件，并关联设计章节、测试用例和实现 PR。需求未确认前标记为草案，禁止将目标值写成 SLA。变更应说明范围、风险、迁移和安全影响。
