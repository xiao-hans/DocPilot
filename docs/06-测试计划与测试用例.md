## 1. 测试目标

验证多租户隔离、文档处理正确性、任务恢复、结果可追溯、审阅流程、搜索和导出安全。测试优先覆盖跨租户越权、敏感文件处理、重复任务、部分失败和持久化恢复等高风险场景。

## 2. 测试范围

### 范围内

需求/设计静态评审、单元、API 集成、数据库迁移、队列/Worker、端到端浏览器、权限与租户隔离、安全、负载/容量、备份恢复、可用性/可访问性。

### 范围外（待具体版本）

未选定的云厂商认证、正式渗透测试认证、未接入的集成商验收和未知监管框架合规认证。

## 3. 测试策略

| 层级 | 重点 | 自动化目标 |
|---|---|---|
| 静态评审 | 需求可验证性、设计威胁面、迁移/回滚、文档追踪 | PR checklist / lint |
| 单元 | 权限策略、状态机、字段校验、幂等、文件名处理、导出转义 | CI 每次提交 |
| 集成 | API+DB、对象存储、队列、Worker、外部服务替身 | CI/预发布 |
| 系统/端到端 | 登录、模板、上传、处理、复核、检索、导出 | 每个发布候选 |
| 安全 | 跨租户对象引用、角色滥用、注入、文件炸弹、CSRF/SSRF、密钥与日志 | 自动化回归+定期人工评估 |
| 性能/恢复 | 上传吞吐、队列积压、搜索分页、Worker 扩展、备份恢复 | 预发布按基线目标执行 |
| 可用性 | 键盘导航、错误反馈、长任务状态、屏幕阅读器语义 | 关键流程抽查 |

## 4. 环境与测试数据

- CI 环境：临时数据库、队列、对象存储模拟器和 OCR/LLM stub；无真实客户数据和生产密钥。
- 预发布：与生产拓扑接近，使用合成/脱敏文档，启用安全日志和可观测性。
- 测试租户至少 A/B 两个、不同角色用户及平台管理员；使用重复 ID/路径参数进行越权验证。
- OCR/LLM 通过录制夹具或 stub 保证稳定；另设受控质量评估集跟踪提取准确率，避免把模型非确定性用例混入普通单测。

### 5.8 G1 在 PostgreSQL 上暴露的方言缺陷（2026-10-03）

全量 259 项用例在 PostgreSQL 与 SQLite 双跑，发现并修复三类只有 PG 才会暴露的问题：

| 缺陷 | 表现 | 根因 | 处理 |
|---|---|---|---|
| 审计游标在 PG 上 422 | `GET /audit-events?before=<created_at>` 返回无 `events` 键 | `document_versions.created_at` 等列声明为 `DateTime(timezone=True)`，SQLite 返回 naive、PG 返回 tz-aware，`isoformat()` 带 `+00:00`；查询串里 `+` 按规范解成空格，FastAPI 解析失败。`tests/test_audit.py::test_audit_pagination_is_descending_and_stable` | `app/services/membership.py` 新增 `_iso_utc()`，UTC 时间戳统一输出 `...Z`，两方言格式一致且可直接回塞查询串 |
| 含 NUL 的结果值无法入库 | `psycopg.DataError: PostgreSQL text fields cannot contain NUL (0x00) bytes` | PostgreSQL 的 text/json 一律拒绝 `\x00`，SQLite 照收；脏文本来自 OCR/人工修订值 | 在两个入库边界剔除 NUL：`app/contexts/search/service.py` 的索引内容、`app/contexts/review/service.py` 的 `revise()` 字符串值；`tests/test_export_formats.py::test_csv_and_xlsx_share_control_chars_whitespace_and_overlong_cells` |
| 用例依赖数据库返回顺序 | `AssertionError: assert ['xlsx', 'csv'] == ['csv', 'xlsx']` | `tests/test_export_formats.py::test_export_is_audited_and_tenant_scoped` 查询审计事件时没有 `ORDER BY`，SQLite 恰好按插入顺序返回，PostgreSQL 不保证顺序。**这是测试缺陷，不是应用缺陷**——导出接口不承诺返回顺序 | 用例改为显式 `order_by(created_at, id)` 且断言不依赖排列（按排序后的集合比较） |

**同一根因的残留项（未在 G1 处理，须在后续阶段收口）**：时间戳序列化只在审计端点统一，其余端点仍按方言返回 naive 或 `+00:00`；NUL 剔除只覆盖复核修订与搜索索引两处入口，机器提取结果直接落 `extraction_results.values` 的路径未覆盖，遇到含 `\x00` 的解析文本仍会在 PG 上写入失败。
