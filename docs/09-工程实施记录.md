## 4.1 文档元数据兼容迁移（2026-10-02）

- 新增 `Document` 与不可变 `DocumentVersion` ORM/迁移。每个新上传文件创建一份文档及一个版本；版本记录原始文件名、相对存储键、SHA-256、扩展名映射的媒体类型、字节数和创建时间，并通过 `job_id` 指向产生它的任务。
- 文档版本到文档使用 `(tenant_id, document_id)` 复合外键；版本到任务使用 `job_id` 单列外键并在任务删除时置空。仓储事务校验任务、版本、文档和所有者的租户上下文一致。
- 新任务快照与文档元数据通过同一个数据库事务提交。元数据提交前不调度处理任务；文件写入或数据库提交失败会删除本次目录并清除未调度的内存任务。
- 新增 `resolve_storage_path()`：拒绝绝对路径、盘符路径、反斜杠和 `..`，并在解析符号链接后再次确认目标位于存储根目录内；上传写入时执行存储键往返校验。多文件版本通过唯一原始文件名与任务快照对应，不依赖时间戳排序。
- 旧任务读取继续使用现有 JSON 快照，不回填历史数据；API 响应和 Excel 导出形状保持兼容。字段定义仍随任务请求提交，模板实体暂未实现。
- 验证：`pytest` 全量 129 项通过；Windows 环境在无法创建目录符号链接时回退到 junction，符号链接越界用例已实际执行。隔离 SQLite 数据库 Alembic upgrade/downgrade/upgrade 通过，`alembic check` 报告无模型漂移。未连接 PostgreSQL，因此 PostgreSQL 迁移未验证。

## 5. 本地开发操作

安装 `requirements.txt` 中的依赖后，开发环境启动时会自动应用待执行的 Alembic 迁移。初始化平台管理员前，在 `.env` 设置高熵 `BOOTSTRAP_TOKEN`，并启动 API；随后通过前端“首次部署？初始化平台”操作，或向 `POST /api/v1/auth/bootstrap` 发送 `X-Bootstrap-Token` 请求头以及 `email`、至少 12 位 `password`、`tenant_name` 字段。该入口成功一次后即不可再次使用。

生产环境必须设置 `APP_ENV=production`，配置 PostgreSQL `DATABASE_URL`，先运行 `alembic upgrade head`，再启动服务；此时旧的无认证 `/api/jobs` 接口返回 404，未构建 Vue 前端则返回 503。会话 Cookie 默认为 Secure，HTTPS 是生产部署前提。PostgreSQL driver 已列入依赖，但本轮未连接或验证真实 PostgreSQL 服务。

测试执行：`python -m pytest`（120 个用例，含租户隔离与认证边界）。测试进程会把数据库与上传/输出目录重定向到临时目录，不会读写本地开发数据。
