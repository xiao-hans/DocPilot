## 1. 目标与范围

把"处理完成即结束"升级为"结果可复核、文档可归档检索"：机器提取结果成为可修订、可确认的资产，文档与工作空间内的任务/文档可筛选浏览，导出扩展 CSV。

本期不实现：全文与字段检索索引（阶段 E）、事件规则与审批（阶段 E）、Webhook 与计量（阶段 F）、对象存储与病毒扫描、原文 PDF 像素级高亮定位（仅交付文本预览）。

`docs/12 §7` 承诺阶段 D 顺带完成"身份/处理编排模块迁入 `app/contexts/**`"。本期把它拆成阶段 D 之后的独立搬迁提交，避免同一变更窗口里既改语义又改路径导致回归失败无法归因；本文件的实现顺序在第 8 节说明。

## 2. 现状缺口（证据）

- `DocumentPipeline` 只保留 `page_count/chars/ocr_applied`，**不持久化解析文本**，因此没有原文预览的数据来源（`app/contexts/processing/pipeline.py` 回填段）。
- 提取结果只活在 `processing_jobs.snapshot.result` JSON 里，无版本、无修订链、无状态，`GET /jobs/{id}/result` 直接读快照。
- 没有租户维度的任务列表端点，也没有文档库列表端点；`FR-030` 的筛选无落点。
- 无 `ExtractionResult`/`ResultRevision`/`ReviewEvent` 实体；`FR-023` 的"修改前后值可审计"与乐观并发无实现。
- `ExcelBuilder` 只输出 XLSX；`FR-032` 要求 CSV 且防注入。

## 3. 上下文与聚合

新增 `review`（提取与复核，核心域）与 `catalog`（文档库读模型）两个上下文；`document asset` 扩展元数据列。

| 聚合根 | 不变式 |
|---|---|
| `ExtractionResult` | 一个文件版本在一个模板版本下只有一条当前结果；`state ∈ {machine, revised, confirmed, rejected}`；`revision_no` 单调递增且与最新 `ResultRevision.revision_no` 一致 |
| `ResultRevision` | 只追加；每次人工保存生成 `revision_no+1`；记录 `values`、`actor_user_id`、`reason`、`source ∈ {machine, human}`；不覆盖历史 |
| 确认/退回权限 | `confirmed` 与 `rejected` 只允许 `reviewer`/`admin`/`owner`；`member` 不得确认自己提交的批次？本期不设此规则，`docs/08` 待确认后再加上；退回必须带 `reason`（1–500 字符） |
| 乐观并发 | 保存修订必须携带 `expected_revision`；判定在数据库层完成（`UPDATE ... WHERE revision_no = expected AND state ∈ 可编辑态` 判 rowcount），不匹配返回 409，绝不静默覆盖；修订链的 `UNIQUE(result_id, revision_no)` 兜住竞态，冲突一律转 409 |
| 确认/退回状态机 | `machine|revised → confirmed`、`machine|revised|confirmed → rejected`；`rejected → confirmed` 禁止（必须先修订产生新值）；退回同时清空 `confirmed_by`/`confirmed_at`，避免"已退回却带着确认人"的读模型 |
| `Document` 元数据 | `labels` 为去重后 ≤10 个、每个 ≤30 字符的列表；`retention_status ∈ {active, purge_scheduled, purged}`；`doc_type`（来自模板名）与 `source ∈ {upload, api, import}` 只增不改语义 |

## 4. 数据模型

新增表（单个 Alembic revision）：

- `document_texts`：`id`、`document_version_id`（FK CASCADE，唯一）、`tenant_id`（FK CASCADE，索引）、`text`（Text，可空）、`char_count`、`extracted_at`。文本是派生数据，不进入 `documents` 主表以保持版本不可变。
- `extraction_results`：`id`、`tenant_id`、`job_id`（FK `processing_jobs` CASCADE）、`document_version_id`（FK CASCADE）、`template_version_id`（可空，复合外键 `→ template_versions(tenant_id,id)`）、`revision_no`、`state`、`values`（JSON，当前值）、`fields`（JSON，冻结的字段定义，保证模板缺失字段时仍可展示）、`warnings`（JSON）、`confirmed_by`/`confirmed_at`（可空）、`created_at`/`updated_at`；唯一 `(job_id, document_version_id)`。
- `result_revisions`：`id`、`result_id`（FK CASCADE）、`revision_no`、`source`、`actor_user_id`（FK SET NULL）、`values`（JSON）、`reason`（可空，≤500）、`created_at`；唯一 `(result_id, revision_no)`。

扩展 `documents`：`doc_type`（String(120)，可空）、`labels`（JSON，默认 `[]`）、`source`（String(20)，默认 `upload`）、`retention_status`（String(20)，默认 `active`）、`updated_at`。

历史兼容：阶段 C 之前完成的任务没有规范化结果行。`GET /jobs/{id}/result` 保持读快照，同时新增 `GET /jobs/{id}/results` 读规范化行；文档库列表对历史任务以快照派生（不回填，与 `docs/10`、`docs/13` 的"不猜历史元数据"原则一致）。

## 5. API 契约

判定顺序沿用 DOC-DD-003 §5.1。前缀除注明外为 `/api/v1/tenants/{tenant_id}`。

| 端点 | 角色 | 说明 |
|---|---|---|
| `GET /results?state=&template_version_id=&job_id=&limit=&offset=` | 任意 active 角色 | 复核队列，按 `updated_at` 倒序分页（`limit` ≤ 100）；`state ∈ {machine, revised, confirmed, rejected, all}`，其他值 422 |
| `GET /results/{result_id}` | 任意 active 角色 | 当前值 + 字段定义 + `revisions` 摘要 |
| `GET /results/{result_id}/revisions` | 任意 active 角色 | 只追加历史，倒序 |
| `GET /document-versions/{version_id}/text` | 任意 active 角色 | 原文预览文本；无文本时返回 `{"char_count": 0, "text": ""}` |
| `PATCH /results/{result_id}` | `reviewer`/`admin`/`owner` | body `{values, reason?, expected_revision}`。`values` 必须**整表单提交**：未知键 422、缺字段 422（缺字段会被静默清空，不能默认沿用旧值）；值只接受标量（字符串/数字/布尔，`null` 表示显式清空），嵌套结构 422；标量按原类型保存，读出后不改类型写回。409 覆盖三种情况：对已确认结果直接改、`expected_revision` 过期、并发下被他人抢先（条件更新 rowcount=0 或修订唯一约束冲突） |
| `POST /results/{result_id}/confirm` | 同上 | 无 body → `state=confirmed`，写 `confirmed_at/by`；已是 `confirmed` 409；`rejected` 直接确认 409 |
| `POST /results/{result_id}/reject` | 同上 | body `{reason}`（必填，1–500）→ `state=rejected` 并清空 `confirmed_by/at`；已是 `rejected` 409 |
| `GET /jobs?status=&template_version_id=&limit=&offset=` | 任意 active 角色 | 租户内任务列表（分页、状态过滤），响应不含文件绝对路径 |
| `GET /documents?label=&doc_type=&retention_status=&source=&q=&from=&to=&limit=&offset=` | 任意 active 角色 | 文档库列表；`retention_status`/`source` 非法值 422；`q` 为**文件名精确匹配**，全文检索留给阶段 E；版本与结果状态各一次批量查询（不逐文档发 SQL） |
| `PATCH /documents/{document_id}` | `member`+，但 `retention_status` 仅 `admin`/`owner` | `{labels?, doc_type?, retention_status?}`；治理字段越权 403，业务字段照常 200；变更写 `document.metadata_updated` 审计 |
| `GET /jobs/{job_id}/export?format=xlsx\|csv` | 任意 active 角色 | 兼容既有 `/excel`；CSV 用 UTF-8 BOM + 全字段引号；两种格式共用 `excel_builder.cell_value/cell_text` 归一（换行统一到 LF、XML 非法控制字符替换为空格、`=+-@` 前缀单引号、超过 32767 字符截断加 `...`），数字在 XLSX 保持数字、CSV 写其文本形式，二者可见内容逐字符一致；导出文件与 `/excel` 缓存分名（`{job}.export.xlsx`），并经"临时文件 + 原子改名"落盘 |

`q` 参数只允许在文档库内做前缀/等值匹配，服务端强制带租户条件；不做模糊打分与全文索引（阶段 E 的 `search` 上下文承担）。

## 6. 关键流程

1. **结果规范化写入**：`DocumentPipeline` 每个文件成功后产出 `ExtractionResult(state=machine, revision_no=1, values, fields, warnings)` + 首条 `ResultRevision(source=machine)` + `document_texts` 行。管线只**暂存**该文件的规范化数据，由下一次快照写入在**同一事务**内落库（`JobRepository.save(after=…)`）：分两次提交时崩溃会留下"新快照 + 旧结果"的混合读视图，导出会读到半新半旧的数据。崩溃恢复沿用阶段 C 的收敛策略，重复写入以 `(job_id, document_version_id)` 唯一索引幂等（存在且仍为 `machine` 才更新机器值，`revised/confirmed/rejected` 不被机器结果覆盖）。
2. **人工修订**：先做载荷校验（未知键/缺字段/非标量 → 422），再执行 `UPDATE … WHERE id AND tenant_id AND revision_no = expected AND state ∈ {machine, revised, rejected}`；rowcount=0 即 409（并发被抢先或状态已变），追加的 `ResultRevision` 由 `UNIQUE(result_id, revision_no)` 兜住剩余竞态，`IntegrityError` 一律 rollback 后转 409。审计与 outbox 事件与结果写入同事务提交。
3. **确认/退回**：状态机 `machine|revised → confirmed`、`machine|revised|confirmed → rejected`（退回必须带理由并清空 `confirmed_by/at`），`rejected → confirmed` 禁止；两条迁移都走条件更新（`WHERE state IN (允许的前态)`），因此并发确认只有一人成功、审计也只写一条。确认不要求 `values` 全部字段非空——空值允许确认，但 `warnings` 必须包含缺失字段提示（FR-022 的"缺失值明确表示"）。
4. **导出**：以 `ExtractionResult` 当前值为源（若存在），否则回落快照；CSV 与 XLSX 共用列顺序（`filename` 首列 + 字段顺序）与同一单元格归一函数，`/excel` 的快照缓存文件与 `/export` 的当前值文件分开命名。

## 7. 安全与兼容约束

- 所有新增查询强制 `tenant_id` 条件；跨租户 ID 一律 404（与阶段 B/C 一致），审计动作新增：`document.metadata_updated`、`result.revised`、`result.confirmed`、`result.rejected`、`job.exported`。修订链查询同样带 `tenant_id`（`ResultRevision.tenant_id` 参与条件，不按 `result_id` 单独放行）。
- 结果与文本是**不可信外部内容**：预览接口只返回纯文本，不返回 HTML；CSV/XLSX 一律走同一注入转义；`values` 的键必须来自冻结字段定义，未知键与缺字段都直接 422（丢弃会让用户在导出文件里看到"少了字段"却不知原因），非标量值同样 422。
- 复核与文档库写入要求 active 成员关系：被移除成员即使持旧会话也必须 403（复用阶段 B 判定，不新增会话撤销）；`documents.retention_status` 属治理面，仅 `admin`/`owner` 可改，`member`/`reviewer` 越权 403。
- 导出写入走"同目录临时文件 + 原子改名"，两个并发请求不会交错写同一个路径；`/export` 与 `/excel` 产物分名，当前值导出不覆盖快照缓存文件。
- 单元格归一对两种格式生效且规则一致：换行统一到 LF（XLSX 的 XML 解析本就会折行）、XML 非法控制字符替换为空格、`=+-@` 前缀单引号、超过 32767 字符截断并加 `...`（Excel 硬上限）。制表符与引号内容原样保留。
- 兼容：既有 `GET /jobs/{id}/result`、`/excel` 行为与响应形状不变；新增字段只增不改。
