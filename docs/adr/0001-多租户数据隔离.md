# ADR-0001：共享 SaaS 的租户数据隔离策略

| 属性 | 内容 |
|---|---|
| 状态 | 提议中，待架构评审 |
| 日期 | 2026-10-02 |
| 决策人 | 待指定 |
| 关联需求 | FR-001–FR-003、NFR-001、R-001 |

## 背景

DocPilot 的目标定位是多个客户共同使用的通用文档平台。客户文件、模板、任务、抽取结果、导出和索引具有敏感性。当前代码没有租户、身份或持久化数据隔离机制，因此目标架构必须把租户作为核心领域边界。

## 决策

首期建议采用共享应用、共享关系数据库和共享对象存储的逻辑多租户架构：所有客户业务记录具有必填 `tenant_id`；每个请求和异步任务由可信身份成员关系产生 TenantScope；数据访问在服务层显式限定租户，并通过复合外键/唯一约束避免跨租户关联。若选用支持成熟策略的 PostgreSQL，评估以 Row-Level Security 作为纵深防御。对象存储使用随机、不含客户名/原文件名的 key，并通过授权访问。

该选择是待评审的首期方向；数据驻留、强隔离或合同要求可能使部分客户需要独立数据库/存储部署。

## 考虑过的方案

| 方案 | 优点 | 缺点 |
|---|---|---|
| 共享库 + `tenant_id` | 成本低、迁移和运营简单、适合早期规模 | 应用层漏过滤影响面大，需严格测试和约束 |
| 每租户独立 schema | 较强逻辑分离，可分客户迁移 | schema 迁移、连接池和跨租户运营复杂 |
| 每租户独立数据库/部署 | 隔离和驻留控制最强 | 成本、升级、备份、监控和版本管理复杂 |

## 后果与控制

- 所有 repository/service 查询必须要求 TenantScope；不得以客户端 tenant_id 替代授权。
- 全量表、缓存 key、队列消息、搜索索引、导出任务和对象键需要租户边界。
- 自动化测试应为 A/B 租户创建同类对象，验证读取、修改、删除、搜索、下载、导出和异步回调均不能串租户。
- 平台运营访问客户内容应最小授权、审计并有明确支持流程。
- 需评估 Row-Level Security 与连接池/异步 worker 上下文的兼容，避免 tenant session 状态泄漏。
- 定义租户删除、数据导出、备份保留、加密密钥和客户隔离升级路径。

## 决策复审条件

首批客户合同或法规要求独立数据驻留/加密密钥；租户规模导致共享库性能或爆炸半径不可接受；正式负载模型显示共享资源无法满足目标；或 RLS/运营控制无法达到风险要求。
