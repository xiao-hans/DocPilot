# ADR-0002：身份会话与关系数据库基础

| 属性 | 内容 |
|---|---|
| 状态 | 已采用；G1 架构评审于 2026-10-03 完成：PostgreSQL 基线经迁移门禁与 259 项用例双方言验证可用，生产供应商/托管方式/高可用仍未定案（G-DEC-04） |
| 日期 | 2026-10-02 |
| 关联需求 | FR-001–FR-003、NFR-001、NFR-003 |

## 背景

平台需要持久化用户、租户、成员关系和会话，并支持本地开发与后续 SaaS 数据库部署。认证与存储最终供应商尚未由产品/运维评审确认，因此先选择可替换的应用接口和便于开发的默认实现。

## 决策

- 使用 SQLAlchemy ORM 与 Alembic 管理关系数据模型和迁移。
- 本地开发默认使用 SQLite；通过 `DATABASE_URL` 配置其他 SQLAlchemy 支持的数据库。生产目标优先评估 PostgreSQL，正式定案需单独架构评审。
- 非开发环境要求 PostgreSQL 数据库 URL；服务启动会拒绝使用 SQLite。生产数据库供应商、托管方式和高可用配置仍未选定。
- 浏览器会话使用高熵不透明随机 token；数据库只保存 token 的 SHA-256 摘要。Cookie 为 HttpOnly、SameSite Strict；HTTPS 环境启用 Secure。
- 写操作通过 `X-CSRF-Token` 校验与会话绑定的随机 CSRF token。
- 密码以带随机盐的 PBKDF2-HMAC-SHA256 摘要保存。
- 初始管理员由配置的一次性 `BOOTSTRAP_TOKEN` 建立，不开放匿名注册入口。
- 开发环境可自动创建当前基础 schema；非开发环境必须显式运行 Alembic migration。

## 后果与限制

- OAuth/SSO、密码重置、邮箱验证、限流、账户恢复和邀请邮件仍未实现；上线前必须补齐并安全评审。
- CSRF 防护依赖浏览器 Cookie 策略和自定义 header；部署若启用跨域 Web，需要增加严格 Origin/CORS 策略并重新评审。
- PBKDF2 参数后续可按部署硬件基准调整；需要在验证时支持渐进式 rehash。
- 生产 PostgreSQL 连接、迁移、连接池、备份与恢复流程仍需验证。
- SQLite 不作为多副本生产任务处理数据库；并发写入能力有限。
- 初始实现没有对创建工作空间做计量/限流，开放用户注册前需增加滥用防护。

## 复审条件

确定托管身份服务或 SSO；接入生产 Postgres；正式确认登录、账户恢复、租户开通策略；或安全评审发现 Cookie/CSRF 模型不满足部署方式时复审。
