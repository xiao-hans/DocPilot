# DocPilot 项目文档

> 项目方向：通用型、多租户文档处理平台。阶段 B–F 已交付；阶段 G 设计已评审，G0 容器环境、G1（本机 Compose + PostgreSQL 迁移门禁 + 备份恢复演练）、G2（RabbitMQ + 自建派发器/Worker + 执行租约与超时回收，见 `docs/adr/0004`）与 G3（`ObjectStorage` 契约 + Local/S3 双实现 + SeaweedFS 本机端点 + 失败补偿与只报告的孤儿审计）已于 2026-10-03 交付，G4（`/result`、`/excel` 改读规范化结果 + 响应时间戳/`NUL`/聚合排序三方言残留收口）、G5（模板/成员邀请/事件规则三块管理界面 + `GET /automation/meta` 单点白名单 + `/readyz` 队列消费者判定 + 10 条 Playwright 端到端用例）与 G6（合成数据容量观测脚本 + `docs/18` 同机基线报告）同日交付。阶段 G 的本地验证目标至此闭合，但性能阈值、数据保留与 RPO/RTO 仍未评审，本地数字不构成生产容量或 SLA。当前容量规划目标为 100 个租户、约 1TB 文件、最多 100 个并发处理任务；只做本地 Docker Compose 开发验证，暂不部署线上服务器。服务等级、合规边界、容量验收阈值与生产技术供应商仍待确认。

## 文档状态约定

- **草案**：待产品负责人和技术负责人评审，不作为已承诺的交付基线。
- **已批准**：范围和验收标准已确认，可据此进行设计、实现和测试。
- **已废弃**：被后续版本或决策替代；保留以供追溯。

需求编号采用 `BR`（业务）、`FR`（功能）、`NFR`（质量属性）、`SEC`（安全）和 `OPS`（运维）。需求变更应同步更新 SRS、设计、测试用例和追踪矩阵。
